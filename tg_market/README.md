# Ринок IT-вакансій у Telegram-каналах

Окремий модуль аналітики, щоденний пайплайн (`main.py`) його не імпортує.
Питання, на які він відповідає: скільки IT-вакансій публікують українські
Telegram-канали, як вони розподілені за напрямами, рівнями й форматом роботи,
які навички просять і які канали дають найбільше унікальних вакансій.

```
python -m tg_market.collect --since 2026-08-01     # збір і класифікація (панель core)
python -m tg_market.analyze                        # дедуплікація і метрики → data/out/*.csv
```

## Як зібрані дані

**Панель каналів.** `channels.csv` містить три групи:
- `core` — канали, які регулярно публікують вакансії. Метрики ринку рахуються
  лише по цій групі.
- `secondary` — канали з меншим потоком вакансій, збираються за потреби.
- `reference` — канали з оглядами ринку, подіями й статтями. Вони лишаються
  в каталозі, але частки ринку не формують.

Каталог ширший (56 каналів у Google Sheets). З нього виключено російськомовний
ринок, спам і мертві канали. Склад панелі змінюється **лише раз на квартал**,
щоб порівняння між періодами було like-for-like.

**Збір.** Модуль читає публічний preview `t.me/s/<канал>` і гортає сторінки
назад через `?before=`. HTML розбирається детерміновано (`parse.py`): id поста,
дата, перегляди, текст. Зовнішні посилання дописуються до тексту, посилання
на t.me відкидаються. `state.json` зберігає останній оброблений пост кожного
каналу, тому повторний запуск бере тільки нові пости.

**Класифікація.** Пости порціями по 10 відправляються в Claude API
(`classify.py`). Модель повертає JSON за фіксованою схемою: чи це вакансія,
а для кожної вакансії — назва, компанія, IT чи ні, напрям, рівень, мінімальний
досвід, навички, формат, зарплата і посилання. Правила віднесення до напрямів
прописані в промпті явно, щоб однакові посади в різних постах
класифікувались однаково.

**Що НЕ зберігається.** Тексти постів і контакти рекрутерів не зберігаються.
У CSV потрапляють лише структуровані поля.

## Перевірки після моделі

1. **Невалідний JSON.** Порція пробується двічі. Якщо відповідь і далі
   невалідна, порція ділиться навпіл рекурсивно, аж до одного поста. Пост, який
   так і не розібрався, пропускається й потрапляє в лог. За серпень–вересень
   2026 у лозі був 1 такий пост із 1 459.
2. **Нерозібрані пости не рахуються як «не вакансія».** Вони мають позначку
   `classified=False` і виключаються зі знаменника частки вакансійних постів.
3. **Детерміновані правки класифікації** (`analyze.reclassify`). Правила по
   назві посади виправляють те, у чому модель стабільно помиляється:
   - креативний дизайн (графіка, моушн, арт-дирекція, SMM-візуал, монтаж)
     переноситься в `marketing`, бо це не IT. UI/UX, product, web і game design
     лишаються в `design`;
   - «аналітики» з НГО та безпекового сектору (MEAL, OSINT, національна
     безпека) переносяться в `non-it`, бо це не аналітика даних.

   Для серпня–вересня 2026 це 35 і 6 правок. Кількість правок друкується
   при кожному запуску.
4. **Нормалізація навичок.** Різні написання однієї навички зводяться до
   найчастішого: `git` і `Git` → одна форма.
5. **Тести** (`tests/test_tg_market.py`) покривають парсинг, нормалізацію полів,
   поділ порцій, дедуплікацію, правки класифікації і тижневі межі.

## Як прибираються дублікати

Одна й та сама вакансія з'являється в кількох каналах, а в дайджестах
повторюється тижнями. Тому є дві одиниці рахунку:
- **згадка**: рядок `vacancies.csv`, використовується для метрик каналу;
- **унікальна вакансія**: використовується для метрик ринку.

Правила злиття (`analyze.dedup`):
1. **Назва нормалізується:** нижній регістр, без уточнень у дужках і без слів
   рівня (junior, senior, стажер…). Рівень — окреме поле, не частина назви.
2. **Порожня компанія** заповнюється найчастішою компанією для такої ж назви.
3. **Ключ злиття** — назва + компанія. Якщо компанії немає, до ключа додається
   формат роботи, бо «SMM Manager» без компанії від різних роботодавців інакше
   злився б в одну вакансію.
4. **Одна вакансія** — це згадки з одним ключем, між сусідніми з яких минуло
   не більше 30 днів. Довша пауза означає нове відкриття вакансії.
5. **Поля кластера:** рівень, формат і напрям беруться як найчастіше значення,
   за винятком `unspecified`. Зарплата вважається вказаною, якщо вона є хоча б
   в одній згадці.

Приклад масштабу: за 01.08–28.09.2026 1 539 згадок дали 1 066 унікальних
вакансій, з них IT — 359.

## Метрики

Усі ринкові метрики — **частки у % поруч із n** (знаменником). Абсолютні
кількості залежать від складу панелі, частки — менше. Якщо n < 30, стоїть
позначка `small_sample`.

| Файл | Що містить |
|---|---|
| `unique_vacancies.csv` | унікальні вакансії з першою/останньою датою, кількістю згадок і каналами |
| `direction_level.csv`, `direction_format.csv`, `direction_salary_stated.csv` | розподіл усередині кожного напряму |
| `weekly_direction.csv`, `weekly_level.csv`, `weekly_format.csv` | тижневі частки, лише **повні** ISO-тижні |
| `skills_by_direction.csv` | частка вакансій напряму, де згадано навичку; `n_with_skills` — скільки вакансій мають хоч одну навичку |
| `channel_metrics.csv` | по каналу: частка вакансійних постів, частка IT, унікальні IT-вакансії на тиждень, коефіцієнт повторів, «опублікував першим», частка ексклюзивних, середні перегляди |

Зрізи: тижневий (у CSV), місячний, квартальний і річний. Дашборди будуються
**щоквартально** по панелі, яка діяла весь квартал.

## Межі методу

- **Це не весь ринок.** Панель — 15 каналів core, вибрана вручну. job-борди
  (DOU, Djinni, robota.ua) і LinkedIn сюди не входять. Висновки стосуються
  Telegram-сегменту.
- **Вакансії без рівня й формату.** Рівень не вказано в ~46% IT-вакансій,
  формат — у ~30%. Це реальна властивість оголошень, модель їх не домислює.
  Тому частки junior/remote — нижня межа.
- **Навички — розріджені дані.** Дайджести часто публікують лише назву посади,
  тож у ~59% вакансій список навичок порожній. Частки навичок читаються разом
  з `n_with_skills`.
- **Дедуплікація евристична.** Та сама вакансія з різними назвами («Data
  Analyst» / «Аналітик даних») не зливається. Різні вакансії з однаковою назвою
  без компанії й формату можуть злитися.
- **Класифікація модельна.** Межі напрямів (BA vs PM, data engineer
  vs analytics) задані правилами в промпті, але окремі випадки спірні.
  Детерміновані правки закривають лише системні помилки, які вже виявлено.
- **Публічний preview Telegram** показує лише публічні канали, інколи
  не відповідає вчасно (тоді канал добирається повторним запуском з
  `--channel`) і не містить реакцій.
- **Тренди.** Один квартал даних — це знімок стану, а не тренд. Сезонність
  стане видно лише після кількох кварталів на незмінній панелі.
- **Лише зарплата «вказана/ні».** Суми витягуються, але валюта й період різні
  (місяць/година/проєкт), тому порівняння сум потребує окремої нормалізації.
