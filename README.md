# Job Search Automation Pipeline

Python-версія щоденного пошуку вакансій, яка раніше жила як текстовий промт
scheduled-задачі. Той самий "мозок" (Claude оцінює вакансії й листи), але:

- скрапінг джерел — окремі Python-модулі, а не браузинг через чат;
- Google Docs/Sheets редагуються **на місці** через `documents.batchUpdate` /
  `spreadsheets.values.append` — без trash+recreate;
- лічильники для метрик рахує Python (`len()` над списками), а не LLM "по
  ходу" — структурно неможливо збитись з рахунку на великих обсягах;
- hr@-домен і "компанія зі списку" визначаються регексом у Python — Claude
  відповідає тільки за те, що код визначити не може (семантика).

## Структура

```
config.py                 — усі бізнес-правила (профіль, пороги, назви файлів, часові пояси)
models.py                 — dataclasses: RawJobPosting, ScoredVacancy, EmailFinding, RunMetrics, SelfCheckResult
scrapers/                 — по одному модулю на джерело (djinni, dou, robota, workua, happymonday)
google_services/          — auth.py, drive.py, docs.py, sheets.py, gmail.py, notify.py (push)
claude_orchestrator/      — prompts.py (тексти), client.py (виклик Anthropic API)
pipeline/                 — step1_vacancies.py, step2_mail.py, step3_metrics.py, step4_selfcheck.py
main.py                   — точка входу, формує фінальний звіт (report_<дата>.md) і шле push
```

## Встановлення

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # і заповни ANTHROPIC_API_KEY
```

## Налаштування Google API

1. Google Cloud Console → створи проєкт (або використай наявний) →
   увімкни APIs: **Google Drive API**, **Google Docs API**, **Google Sheets
   API**, **Gmail API**.
2. APIs & Services → Credentials → Create Credentials → OAuth client ID →
   Application type: **Desktop app**. Завантаж JSON, поклади як
   `credentials/credentials.json`.
3. Перший запуск `python main.py` відкриє браузер для логіну Google —
   увійди тим акаунтом, де лежить папка з резюме. Після логіну збережеться
   `credentials/token.json` (автооновлюється, повторний логін не потрібен,
   поки Google не відкличе доступ).
4. **Для headless-сервера/cron**: крок 3 вимагає браузера, тому token.json
   треба один раз згенерувати на машині з браузером (наприклад, локально)
   і скопіювати `credentials/token.json` на сервер. Далі пайплайн працює
   без інтерактивного логіну.

`credentials/` — обов'язково додай у `.gitignore`, там лежать секрети.

## Запуск

```bash
python main.py
```

Виводить звіт у stdout і зберігає в `reports/report_<YYYY-MM-DD>.md`.

## Планування запуску

Будь-який з варіантів — обери зручний:

- **cron** (Linux/macOS): `0 9 * * * cd /path/to/job_search_pipeline && venv/bin/python main.py >> logs/cron.log 2>&1`
- **systemd timer** — якщо потрібен більш керований запуск із логами.
- **GitHub Actions** (`schedule: cron: '0 9 * * *'`) — зручно, якщо код у
  приватному репозиторії; секрети (ANTHROPIC_API_KEY, вміст token.json) —
  через GitHub Secrets.

## Push-сповіщення

Чат-версія промпту слала push через нативний інструмент телефону
користувача — самостійний скрипт такого не має "з коробки". Заміна —
[ntfy.sh](https://ntfy.sh): безкоштовний публічний pub/sub без реєстрації.

1. Постав застосунок ntfy (iOS/Android) або відкрий
   `https://ntfy.sh/<унікальна-назва-теми>` в браузері й підпишись.
2. Впиши ту саму назву теми в `.env` як `PUSH_NTFY_TOPIC` (тема — де-факто
   пароль: обери важкозгадувану назву, тема публічна для будь-кого, хто її
   знає).
3. Якщо `PUSH_NTFY_TOPIC` не задано — `google_services/notify.py` пише
   попередження в лог і пропускає крок; запуск через це не падає (звіт
   однаково є в stdout і в `reports/report_<дата>.md`).

Якщо потрібен інший канал (email, Telegram-бот, Slack) — заміни тіло
`notify.send_push()` на відповідний виклик, сигнатура (`message: str ->
bool`) і місце виклику в `main.py` (в самому кінці, безумовно) лишаються
ті самі.

## Якщо requests+BeautifulSoup не бачить вакансій (SPA-сайти)

`scrapers/robota.py` уже має запасний варіант через вбудований JSON-стан
сторінки. Якщо і це не спрацює на практиці (сайт повністю рендериться
клієнтським JS без початкового стану в HTML) — заміни `requests.get` у
конкретному скрапері на `playwright` (`pip install playwright && playwright
install chromium`), не чіпаючи решту пайплайна — контракт `scrape() ->
Iterator[RawJobPosting]` лишається той самий.

## Важливі гарантії, збережені з текстової версії промпту

- **НІКОЛИ не пише** у `Мої відгуки на вакансію.xlsx` (id у
  `config.FORBIDDEN_FILE_IDS`) — `google_services/drive.py::guard_not_forbidden`
  кидає виключення при спробі, це не забудеш прибрати випадково.
- Дедублікація вакансій — **21-денне** вікно логу (`config.DEDUP_LOG_MAX_AGE_DAYS`,
  свідомий запас на пропущені запуски, не 7 — тижнева пауза між запусками
  реалістична), окремий файл "Лог показаних вакансій (автопошук)" у тій
  самій Drive-папці, що й резюме.
- **Дворівнева страховка дедублікації**, якщо лог недоступний навіть після
  повторної спроби читання: Рівень 2 — читання-лише URL-колонки
  ("Посилання на вакансію") таблиці "Ворошилов відгуки на вакансії"
  (`pipeline/step1_vacancies.py::_level2_tracker_urls`). НЕ звіряє за
  назвою компанії (та сама компанія легітимно публікує кілька вакансій).
  Якщо активується — у звіті з'являється речення з поясненням межі цього
  рівня (охоплює лише вакансії, на які подано). Якщо недоступні обидва
  рівні — показ без дедублікації, з явним попередженням.
- **Дві навмисно різні дати за запуск** (`config.py`, розділ "Часові
  пояси"): усі три службові файли (лог, метрики, результат Кроку 4)
  пишуть дату/час у UTC; фільтр "сьогодні/вчора" для дати ПУБЛІКАЦІЇ
  вакансії (Крок 1) — за місцевим часом кандидата (Europe/Warsaw). Це
  різні поняття часу з різним призначенням, не переплутати.
- Крок 2 виконується завжди, незалежно від результату Кроку 1 (`main.py`
  ловить помилку Кроку 1 окремо й не блокує Крок 2/3/4).
- Джерело недоступне → позначається "недоступне" в метриках, решта джерел
  все одно перевіряється.
- **Крок 4 — самоперевірка запуску** (`pipeline/step4_selfcheck.py`),
  виконується завжди, незалежно від результату Кроків 1-3: OK/ЧАСТКОВО/НЕ
  ВИКОНАНО по кожному кроку, спосіб збору «знайдено» (перша_сторінка у
  всіх скраперів — пагінація поки не реалізована, див. "Відомі
  обмеження"), конверсія показано/знайдено (або явне "н/д" при
  знайдено=0), порівнюваність тренду (сторого 5/5 джерел), і евристичний
  сигнал "3+ запуски поспіль лише Low/нуль при 5/5" — рахується з
  історії файлу "Результат щоденної перевірки" (не статистичне правило,
  поріг можна скоригувати в `config.LOW_MATCH_STREAK_HEURISTIC_RUNS`).
  Результат дублюється в цей файл (`values.append`, без обмеження за
  довжиною — легкий аудит-лог).
- **Push-сповіщення наприкінці КОЖНОГО запуску, безумовно** (навіть якщо
  нових вакансій немає чи щось вище провалилось) — через ntfy.sh, див.
  `.env.example` (`PUSH_NTFY_TOPIC`) і розділ "Push-сповіщення" нижче.

## Відомі обмеження й що варто перевірити перед першим "бойовим" запуском

1. **CSS-селектори в `scrapers/*.py` — орієнтовні.** Пісочниця розробки не
   мала прямого доступу в інтернет (тільки через окремий інструмент
   рендерингу), тому селектори не звірені з живим HTML. Перед продакшеном
   запусти кожен скрапер окремо (`python -m scrapers.djinni` тощо) і
   перевір, чи знаходяться вакансії.
2. Claude API — платний виклик за кожен запуск (батчі по ~40 вакансій на
   виклик для Кроку 1, один виклик для Кроку 2). Онови `CLAUDE_MODEL` у
   `.env`, якщо потрібна інша модель.
3. Gmail query `_build_query` у `google_services/gmail.py` використовує
   `from:hr@*` — це грубе наближення; звузь за потреби.
4. **Жоден скрапер не гортає сторінки** — кожен бере лише статичну(і)
   keyword-сторінку(и) (`COLLECTION_METHOD = "перша_сторінка"` у кожному
   модулі `scrapers/*.py`). Це чесно відображено в Кроці 4 (`спосіб збору
   «знайдено»`), а не приховано — але означає, що колонка 2 метрики
   ("знайдено до фільтрів") відображає лише перший екран видачі кожного
   джерела, не весь ринок. Якщо знадобиться "усі_сторінки" — додай
   пагінацію в конкретний скрапер і зміни його `COLLECTION_METHOD`.
5. **"Крок 3 (додатковий блок)" чат-версії — оновлення таблиці "Ворошилов
   відгуки на вакансії" з фактів розмовної пам'яті — у Python-пайплайні
   НЕ реалізовано.** Це не недогляд, а структурне обмеження: той крок
   читає memory-файли акаунту Claude (`/areas/job-search.md` тощо), до
   яких автономний cron-скрипт доступу не має. `pipeline/step4_selfcheck.py`
   завжди позначає цей блок "НЕ ВИКОНАНО" з поясненням. Таблицю відгуків
   і надалі оновлюй або вручну, або окремим запитом у чаті з Claude.
6. **Push-сповіщення вимагає ручного налаштування** `PUSH_NTFY_TOPIC` у
   `.env` (див. розділ "Push-сповіщення" вище) — без нього крок мовчки
   пропускається (з попередженням у лог), запуск не падає.
